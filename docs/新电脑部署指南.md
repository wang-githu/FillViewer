# 新电脑部署指南（3D 画面系统）

> 目标：在一台**全新的 Windows 电脑**上把这个 3D 监控画面跑起来。
> 全过程只需拷贝目录 + 装 Python + 改一个配置文件，不用重新搭建。

---

## 0. 先想清楚：新电脑是哪一种角色

| 形态 | 新电脑做什么 | WinCC 在哪 | 要做的事 |
|---|---|---|---|
| **A. 纯显示端**（最常见） | 只跑浏览器画面 | 另一台电脑（已有的 WinCC 服务器） | 拷贝目录 → 装 Python → 改 `config.json` 指向 WinCC 主机 |
| **B. 本机就是 WinCC 服务器** | 显示 + WinCC 同机 | 本机 | 先在本机配好 WinCC REST 服务，再拷目录 |
| **C. 独立展示机 + 大屏** | 只显示，可能接电视/大屏 | 另一台 | 同 A，另加开机自启 + 全屏 |

**A 和 C 不需要装 WinCC**，只要有网络能访问到 WinCC 服务器的 8092 端口就够了。

---

## 1. 前置条件（逐条确认）

- [ ] Windows 10 / 11（64 位），能正常上桌面
- [ ] 硬盘至少 **1 GB** 空余（程序 180 MB + Python 约 150 MB + 余量）
- [ ] **Python 3.9 及以上**（3.12 验证过；不需要 pip 装任何包，全部标准库）
- [ ] 一台浏览器（Edge / Chrome 都行；WinCC 自带的 CEF 也行）
- [ ] 能 `ping` 通 WinCC 服务器主机名，且 8092 端口可达（见第 6 节）

---

## 2. 拷贝程序目录

把**整台电脑上能跑的那一份** `C:\FillViewer` 整个拷到新机器的同一路径：

```powershell
# 在旧电脑上打包（保持目录结构）
robocopy C:\FillViewer \\新机器\c$\FillViewer /E /XD logs __pycache__ /XF *.log
```

也可以直接复制到 U 盘再拖过去。**建议路径保持 `C:\FillViewer`**（脚本里都是相对路径，但少一个变量少一个坑）。

关键子目录：

```
C:\FillViewer\
  server.py            后台服务
  config.json          ★ 唯一要改的文件（REST 地址/账号）
  app\studio.html      配置台
  app\runtime.html     运行画面
  js\                  three.js（离线，不联网）
  projects\            各项目的模型与配置
  data\                变量表、归档表
  models\              原始 GLB 备份
  logs\                运行日志（出问题先看这里）
  tools\start_server.cmd   服务启动器（自动找 Python）
  启动3D配置台.cmd
  启动3D运行画面.cmd
```

---

## 3. 装 Python（二选一）

### 方式一：官方安装（推荐，5 分钟）

1. 打开 https://www.python.org/downloads/windows/ 下载 **Windows installer (64-bit)**（3.12.x 即可）
2. 安装时**务必勾选** `Add python.exe to PATH`
3. 装完打开 cmd 验证：

```
python -V
```

能看到版本号即成功。

> 不需要 `pip install` 任何东西。整个程序只用标准库。

### 方式二：便携版（不想装东西 / 离线）

把任意一个便携 Python（或从别的机器拷一份完整的 Python 目录）放到：

```
C:\FillViewer\python\python.exe
```

启动器会**优先**用它，完全不碰系统 PATH。

---

## 4. 改 `config.json`（唯一需要改的配置）

用记事本打开 `C:\FillViewer\config.json`：

```json
{
  "restBase": "https://YOUR-WINCC-HOST:8092/WinCCRestService",
  "restUser": "YOUR-WINCC-USER",
  "restPass": "YOUR-WINCC-PASSWORD"
}
```

- `restBase`：**WinCC 服务器的地址**，格式固定
  `https://<WinCC主机名或IP>:<端口>/WinCCRestService`
  例：`https://192.168.10.102:8092/WinCCRestService`
- `restUser` / `restPass`：WinCC 里的用户账号（不是 Windows 账号）

> 小提示：WinCC 的 REST 用**自签名证书**，程序已自动跳过证书校验，不用装证书。
> 但如果填的是 IP，而证书是给主机名签的，有些环境会握手失败 —— **优先用主机名**，不行再试 IP。

改完保存即可，不用重启电脑。服务下次启动就生效；服务已在运行时，改完在页面上点一次「刷新」或重启服务。

---

## 5. 启动

双击 **`启动3D运行画面.cmd`**（现场用）或 **`启动3D配置台.cmd`**（要改绑定时用）。

脚本会：

1. 检查 8099 端口是否已被占用（占用了就直接用，不会起第二个）
2. 依次找 Python：`C:\FillViewer\python\python.exe` → PATH 里的 `python.exe` → `py.exe`
3. 后台启动 `server.py`
4. 打开浏览器 `http://127.0.0.1:8099/app/runtime.html`

看不到窗口是正常的（后台服务），浏览器里能打开就是成功。

---

## 6. 网络与防火墙

### 在显示端验证能连到 WinCC

```powershell
# 1) 主机名能解析
ping YOUR-WINCC-HOST

# 2) 8092 端口通（返回 True 就行）
Test-NetConnection YOUR-WINCC-HOST -Port 8092
```

### 如果连不通

在 **WinCC 服务器**上放行 8092 入站：

```powershell
New-NetFirewallRule -DisplayName "WinCC REST 8092" -Direction Inbound `
  -Protocol TCP -LocalPort 8092 -Action Allow
```

## 7. 验证清单（部署完照着做一遍）

| # | 做什么 | 期望 |
|---|---|---|
| 1 | 浏览器打开 `http://127.0.0.1:8099/api/config` | 返回 JSON，`restBase` 是你填的地址 |
| 2 | 打开 `http://127.0.0.1:8099/api/live` | `src` 是 `rest`（走 REST）或 `file`（退回文件桥），`values` 里有变量 |
| 3 | 打开 `http://127.0.0.1:8099/app/runtime.html` | 看到 3D 模型 + 悬浮看板 |
| 4 | 看板上的数字 | 不是 `—`，且和 WinCC 画面上一致 |
| 5 | 看左上角 HUD | `数据源：WinCC REST` 或 `WinCC 动作(文件)` |
| 6 | 打开 `C:\FillViewer\logs\server.log` | 有启动时间戳，无 Traceback |

`src: file` 说明 REST 没通、退回了 WinCC 全局脚本写文件那条老路 —— 能用但不是最快的，建议按第 6 节排查。

## 8. 如果新电脑**就是** WinCC 服务器

先在本机把 WinCC 的 REST 服务配好，再拷程序目录。

### 8.1 打开启动项

WinCC 资源管理器 → 计算机 → 属性 → **启动** 页 → 勾选 **`REST 服务`** → 确定。

### 8.2 改端口（默认 34568，按需改）

```
HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Siemens\WinCC\REST\CCRestService\Config
    RestService.Port        = 8092
    RestService.HostName    = <本机主机名>
    RestService.RequestLimit = 1000
    RestService.RequestWindowSeconds = 10
```

（改注册表需要管理员权限，改完重启运行系统。）

### 8.3 确认证书绑定

```powershell
netsh http show sslcert | findstr /C:"8092"
```

能看到 `0.0.0.0:8092` 和证书哈希就说明绑定好了。

### 8.4 验证服务

浏览器打开：

```
https://<本机主机名>:8092/WinCCRestService
```

能返回下面这种 JSON 就成功：

```json
{"description":"SIMATIC WinCC SCADA",
 "possibleCollections":["namespaces","tagManagement","alarmLogging","tagLogging"],
 "winccVersion":"V8.1 Upd7","projectName":"...","serverName":"..."}
```

> 注意：点「继续访问」接受自签名证书。
> **端口 8092 的监听进程是 PID 4（http.sys），不是 CCRestService.exe** —— 用「看进程有没有开端口」是查不出来的。

### 8.5 放开变量读权限

REST 默认对大多数变量返回 `{"error":"Forbidden"}`。需要在 WinCC 变量属性里给该变量设置读授权，或给用户组加权限。写值同理需要写授权。

## 9. 开机自启（现场展示机建议开）

管理员 PowerShell：

```powershell
schtasks /create /tn "FillViewer服务" `
  /tr "C:\FillViewer\tools\start_server.cmd" `
  /sc onlogon /rl highest /f
```

再把 `启动3D运行画面.cmd` 的快捷方式放进：

```
C:\Users\<用户名>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup
```

如果需要全屏无地址栏，用 Edge 的 kiosk 模式：

```powershell
msedge --kiosk http://127.0.0.1:8099/app/runtime.html --edge-kiosk-type=fullscreen
```

---

## 10. 换 WinCC 服务器 / 换项目

- **只换 WinCC 地址** → 改 `config.json` 的 `restBase`，重启服务
- **换显示的项目** → 打开配置台，左上角下拉选另一个项目，或 `runtime.html?p=项目id`
- **新建一套系统**（另一套充填/选厂）→

```powershell
C:\FillViewer\tools\new_system.ps1 -Name 三号充填 -Port 8100
```

会生成 `C:\FillViewer_三号充填`，独立端口、独立数据，两边互不影响。

## 11. 排错表

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 cmd 一闪而过 | 没装 Python | 装 Python 勾 PATH，或放便携版到 `C:\FillViewer\python\` |
| 浏览器打不开 8099 | 服务没起来 | 看 `logs\server.log` 最后几行 |
| 日志写「端口被占用」 | 已有另一个实例 / 别的程序占了 | `netstat -ano | findstr 8099` 找到 PID 结束 |
| 页面能开但没模型 | 项目里没导模型 | 配置台导入 GLB（文件名纯 ASCII） |
| 看板全是 `—` | 变量没读到 | 检查 `/api/live` 返回；`config.json` 地址/账号 |
| `src` 一直是 `file` | REST 没通 | 第 6 节网络排查；确认 WinCC 启动项勾了 REST |
| 数字不刷新 | WinCC 全局脚本没跑 | 老方案才需要；走 REST 不需要脚本 |
| 证书报错 | 自签名 | 程序已跳过校验；仍报错则换主机名重试 |
| 双击运行画面进错项目 | 自动选了最近修改的项目 | 用 `runtime.html?p=项目id` 指定 |
| 中文乱码 | cmd 用了 GBK | 启动器已改纯 ASCII，不会乱码 |

---

## 12. 一句话版本

> 拷 `C:\FillViewer` → 装 Python → 改 `config.json` 里的地址账号 → 双击 `启动3D运行画面.cmd`。
> 四步，十分钟。
