# FillViewer 使用说明

> 版本 v0.1.0 ｜ 适用：Windows / Linux / macOS ｜ 服务端 Python 3.9+，客户端任意现代浏览器
>
> 本文是**面向使用者**的完整手册。想了解内部实现（REST 批量接口、管道着色器算法、Postman 用例），见 `docs/` 下另外三篇教程。

---

## 1. 这是什么

FillViewer 把 **WinCC / PLC 的实时数据** 映射到 **浏览器里的 3D 模型**上：设备按状态变色或闪烁、罐体按液位升降、电机按转速旋转、管道里跑发光流动的粒子、设备旁贴实时数据卡片。

它的定位是 **WinCC 自带 3D 控件的替代方案**：

| | WinCC 3D 控件 | FillViewer |
|---|---|---|
| 模型格式 | Collada (.dae) | glTF / GLB（Blender 直接导出） |
| 材质 | 受限 | PBR 基本全支持 |
| 动画 | 整体旋转 / 位移 / 缩放 | 变色、渐变、液位、旋转调速、**管道流动**、闪烁 |
| 配置方式 | 改脚本 | **网页配置台点选** |
| 客户端 | 每台装授权 | 任意现代浏览器（大屏、平板、手机） |
| 数据源 | WinCC | WinCC REST，或任意程序写一个 JSON 文件（离线可用） |

**一句话架构**：

```
WinCC REST ─┐
            ├─> server.py（Python 标准库，:8099）─> 浏览器 three.js 渲染
data.json  ─┘        ↑ 配置（绑定/展板/管道）存在 projects/<项目>/*.json
```

## 2. 运行环境

| 项 | 要求 |
|---|---|
| 服务端 | Python **3.9+**，只用标准库，**不需要 pip 安装任何依赖** |
| 操作系统 | Windows 10/11、Linux、macOS 均可 |
| 浏览器 | Chrome / Edge 100+（推荐），Firefox 亦可用 |
| 端口 | 默认 **8099**，用环境变量 `FILLVIEWER_PORT` 可改 |
| 分辨率 | 建议 ≥ 1920×1080；大屏/触摸屏可用 kiosk 全屏 |
| 硬件 | 集成显卡可跑；模型面数很大时建议独显 |

> 浏览器必须是能跑 WebGL2 的版本。若在虚拟机/远程桌面里发现画面发灰或帧率很低，属于软件渲染降级，属正常现象。

## 3. 三分钟跑起来

1. 解压 / `git clone` 到任意目录（路径里有中文也可以）。
2. Windows 双击 **`run.cmd`**；Linux / macOS 执行 **`./run.sh`** 或 `python3 server.py`。
3. 浏览器打开 **http://127.0.0.1:8099/** ，进入首页。
4. 点 **运行画面** —— 看到示例场景（罐体、搅拌机、管道、两块数据卡片）即成功。

首次运行**不需要 WinCC**：服务端读不到 REST 时会自动回落到 `data/data.json` 里的示例数据，动画照常演示。

改端口：

```bash
set FILLVIEWER_PORT=8100 && run.cmd            # Windows
FILLVIEWER_PORT=8100 python3 server.py         # Linux / macOS
```

## 4. 界面导览

### 4.1 首页 `index.html`

四个入口：运行画面 / 配置台 / 变量数据 / 使用说明。

### 4.2 配置台 `app/studio.html`

顶栏：`项目 ▾` `新建` `导入模型` `按名自动绑定` `保存` `打开运行画面` `变量数据`

左侧：**对象树**（搜索框可过滤，显示每个对象的三角面数，点选即选中）
中间：**3D 预览**（左键拖动旋转、滚轮缩放、右键平移，点设备即选中）
右侧：五个页签

| 页签 | 作用 |
|---|---|
| **绑定** | 对象 → 变量，让它变色 / 缩放 / 旋转 / 闪烁 |
| **展板** | 设备旁的实时数据卡片，可拖动摆位、可写回数值 |
| **管道** | 把若干管道对象组成一条管线，做流动/高亮动画 |
| **全部** | 所有绑定 / 展板 / 管线的清单，一键检查规则体检 |
| **设置** | REST 连接、画质、备份回滚、点击回写、变量表、运行选项、版本历史 |

> 三个页签里的操作都要点顶栏 **`保存`** 才写盘。展板页有独立的「保存展板（并退出）」。

### 4.3 运行画面 `app/runtime.html`

- 全屏 3D 现场画面，展板跟随设备或固定在空间坐标。
- 左上角只在**出问题时**出现红色提示条，直接写明原因（例如「有 1 个变量没取到值…（Forbidden）｜WinCC 未给该变量 REST 读授权」）。
- 鼠标：左键拖动旋转、滚轮缩放、右键平移、双击展板数值可写入（该行需勾选「允许写入」）。
- 右下角一行浅色提示文字说明鼠标操作。

### 4.4 变量数据页 `app/vardata.html`

分页浏览整张变量表（几千条也流畅），可按「有值 / 可写 / 读取失败 / 未检测」筛选，按系统分类过滤，支持「检测本页」（批量真读一次）、单变量读取、可写变量直接写入测试。导入变量表后这一页是排查数据问题的第一现场。

## 5. 准备模型（Blender → GLB）

### 5.1 导出设置

| 项 | 建议 |
|---|---|
| 格式 | **glTF 2.0 二进制 `.glb`**（单文件，含材质） |
| 单位 | 米（1 Blender 单位 = 1 米），坐标轴用 glTF 默认 Y-up |
| 三角面 | 建议 ≤ 50 万；大场景把重复件合并、静态文字减面 |
| 材质 | Principled BSDF 基础色即可；**避免金属度 = 1.0**（页面无环境贴图会发黑） |
| 动画 | 不需要（动画全由数据驱动）；导出时可勾掉动画/顶点色 |
| 灯光 | 需要时导出太阳光，强度 1~3（不要用物理单位换算，否则过曝） |

### 5.2 命名是绑定效率的关键

对象名就是绑定的唯一凭据。建议：

- **按设备语义命名**，并且与变量名共享前缀，例如对象 `Demo_Tank`、变量 `Demo_Level` —— 这样「按名自动绑定」能一次配好。
- 中文名、空格、下划线都可以，但 **`.` `[` `]` `:` `/` 这几个字符 three.js 会剥掉**（系统已做归一化匹配，不用手动改名）。
- 同一个设备的罐体、支腿、爬梯如果是多个对象，建议统一前缀（`Demo_Tank`、`Demo_Tank_Base`），后续可一起绑定。

### 5.3 导入

配置台顶栏 **`导入模型`** → 选择 `.glb`，文件会进 `projects/<当前项目>/model/`，并自动设为当前模型。也可以直接手动拷文件再在项目设置里选。

> 换模型后原有绑定的对象名若对不上，右上角「规则体检」会列出来，并给出相似对象候选，点一下即可换绑。

## 6. 绑定：让模型跟着数据动

### 6.1 三种选中方式

1. 左侧对象树点选；
2. 3D 里直接点实体（推荐，所见即所得）；
3. 顶栏 **`按名自动绑定`** —— 按「对象名 ≈ 变量名」批量生成绑定，适合命名规范的项目。

### 6.2 六种绑定类型

| 类型 | 数据怎么用 | 典型场景 |
|---|---|---|
| **颜色（按状态 / 阈值）** | 值落在 `[最小, 最大]` 内 → 涂色，否则恢复原色 | 阀门开/关、电机运行/停止 |
| **颜色渐变** | 值在范围内线性插值两端点色（HSL 过渡） | 电流/开度/温度的热度示意 |
| **缩放（按数值，纵向）** | 按比例纵向缩放，**底面固定不动** | 罐体液位、料仓料位 |
| **旋转（按数值）** | 值 × 系数 = 角度 | 阀门开度角、指针 |
| **旋转动画（启停 + 调速）** | 「启停变量」非 0 才转，转速由数值缩放 | 电机、风机、耙架、螺旋 |
| **状态规则（多变量 → 颜色）** | 一组规则按**从上到下**顺序取第一条命中；都不命中恢复原色 | 一台设备 4 条规则：停机灰 / 运行绿 / 报警黄闪 / 故障红闪 |

每种类型都有：**变量**（也可直接填固定数字，不接 PLC 也能演示）、**范围 最小/最大**、**颜色**。

旋转类额外有：
- **旋转轴**：`Y 轴（竖直，俯视看圈）` / `X 轴（水平，绕 X 侧翻）` / `Z 轴（水平，绕 Z 侧翻）`
- **旋转方向**：`顺时针（俯视）` / `逆时针（俯视）` —— 与实际相反就选另一个
- **最大转速**：rad/s（界面同时显示 ≈ 每秒多少转）
- **调速变量 + 满速值**（仅「旋转动画」）：转速随变量线性变化

状态规则每行：**变量 + 判断（等于某值 / 区间 最小~最大）+ 颜色 + 闪烁**；顶部可设**闪烁频率 Hz**。留空上限表示不封顶。

### 6.3 常见坑与自检

- **启停变量绑错设备**：界面会红字提示「启停变量属于 `X`，与本对象 `Y` 不是同一台设备」，并给一键改正按钮。
- **值对但不变色**：先看「全部」页签的**规则体检**（会列出失效的变量 / 对象，并给候选换绑）；再看变量数据页确认该变量**当前真值**和读取时间。
- **变量名不存在**：WinCC 里没这个变量时 REST 返回 `Not Found`，绑定不会生效。
- **固定数字**：不想接 PLC 时，变量处填数字即可（转速/角度都能直接指定）。

## 7. 展板：把数字贴在设备旁

### 7.1 字段

| 字段 | 说明 |
|---|---|
| 对象 | 展板跟随哪个设备（也可用固定坐标，不跟随） |
| 标题 | 卡片标题，如「浓密机」 |
| 宽度 / 字号 | px；留空 = 按内容自适应 |
| 固定位置 + 坐标 X/Y/Z | 勾选后使用绝对坐标，不勾则跟随对象 |
| 显示控制 → 变量 | 值 = 0 显示、≠ 0 隐藏；留空 = 始终显示 |
| 行 | 每行 = 标签 + 变量 + 单位 + 小数位 + 千分位 + 是否允许写入 |

### 7.2 摆放（在 3D 里直接拖）

- 先点展板卡片载入右侧表单，再在 3D 里拖动它：
  - **直接拖** = 在当前视角平面上移动；
  - **Shift + 拖** = 只上下（Y）；
  - **Alt + 拖** = 只前后（深度）；
  - **Ctrl** = 0.1 m 步进吸附。
- 靠近**其它展板**会自动对齐并画青色虚线提示；靠近**设备**会自动吸到设备顶部。
- 也可以点「在 3D 里点一下定位置」，然后在 3D 里点一个位置直接取坐标。

### 7.3 批量与模板

- **套用到所有展板**：把当前宽度/字号一次性应用到全部展板。
- **保存当前看板为模板 / 套用到当前看板 / 删除模板**：布局与行结构可复用（套用时保留当前看板的绑定对象）。
- **预览全部展板**：一次性显示所有展板（含实时值），用来检查有没有重叠遮挡。

### 7.4 允许写入

某一行勾选「允许写入」后，**运行画面里双击该数值即可写回**。前提：
1. 该变量在 WinCC 里开 **REST 写权限**；
2. 该行确实是可写变量（变量表里「可写」= 是）。

写入成功与否以 WinCC 返回的 `errorcode` 为准：HTTP 200 但带 `{"error":"Forbidden"}` 表示没权限，界面会提示。

## 8. 管道流动

### 8.1 建一条管线

1. 切到**管道**页签；
2. 左侧树或 3D 里**直接点**选管道对象（**再点一次取消**，不需要按 Ctrl；Ctrl/Shift 追加也行）；
3. 点 **`把选中的对象建成管线`** → 生成一张管线卡片。

### 8.2 条件表达式

卡片里的「条件」决定这条管线什么时候动，语法支持：

```
变量名 / 数字 / >  >=  <  <=  ==  !=  &&  ||  !  ( )  +  -  *  /
```

示例：

```
Demo_Flow > 1                     流量大于 1 才流动
Demo_ValveA_Open == 1 && Demo_Flow > 0.5
Demo_Pump_Run == 1 || Demo_ValveB_Open == 1
(Demo_Flow > 0) && !(Demo_Level > 4)
```

### 8.3 外观参数

| 参数 | 说明 |
|---|---|
| 模式 | 只流动 / 只高亮 / 高亮 + 流动 |
| 颜色 | 高亮或粒子带的颜色 |
| 速度 / 间距 | 流动快慢与粒子间隔 |
| 粒子数 / 长度 / 拖尾 | 同时几颗、每颗本体多长（米）、尾巴多长（米） |
| 调速 + 满速值 | 用流量变量控制速度（流量越大流越快）；留空则固定速度 |
| 方向 + 斜坡 | 正/反向；首尾淡入淡出程度 |

### 8.4 提示

- 流动是**着色器**实现的：按管道自身轴向投影出的发光色带，**弯头处也能连续扫过**（不是贴一张移动贴图）。
- 想省性能：一条管线里合并尽量多的管子、减小粒子数；不需要的管线直接删掉。
- **存为模板 / 套用模板**：把颜色、速度、粒子等外观参数存下来，给别的管线一键套用（不含对象与条件）。

## 9. 接入自己的 WinCC

### 9.1 WinCC 侧准备

1. WinCC V8.x 项目管理器 → **计算机属性 → 启动** → 勾选 **REST 服务**（需对应许可）。
2. REST 服务默认地址：`https://<主机名>:8092/WinCCRestService`。
3. **给变量开 REST 权限**：变量管理器里选中变量 → 属性 → 「REST API」组，分别配置**读 / 写**授权；用户管理器里给 REST 用户分配相应权限。
   > 没开权限的变量读会返回 `Forbidden`（HTTP 仍可能是 200），运行画面红条会直接显示这一点。

### 9.2 填配置

把 `config.example.json` 复制成 `config.json`：

```json
{
  "restBase": "https://YOUR-WINCC-HOST:8092/WinCCRestService",
  "restUser": "YOUR-USER",
  "restPass": "YOUR-PASSWORD",
  "liveTtl": 200
}
```

或者直接在配置台 **设置 → REST 连接** 里填（保存后立即生效，不用重启服务）。

### 9.3 导入变量表

设置页 → 变量表 → 导入。两种来源都行：

1. WinCC 变量管理里 **导出 `.txt`（UTF-16，Tab 分隔）**；
2. 自己写 CSV，表头三列：`变量名,注释,可写`（可写填 1/0）。

导入后变量数据页即可浏览，绑定页的变量下拉也会带上这些名字和注释。

### 9.4 验证

- 浏览器打开 `http://127.0.0.1:8099/api/live`，看 `"src"`：
  - `"rest"` = 正在读 WinCC；
  - `"file"` = 回落到了 `data/data.json`（说明 REST 没连上或没配置）。
- 变量数据页点「检测本页」，看质量码与时间列是否在刷新。
- 配置台设置页有「测试连接」类按钮（REST 自检），会直接回报 HTTP 码与错误原因。

### 9.5 不想开 REST 的替代方案

把 `wincc/` 里的 VBS 全局脚本挂到 WinCC 上（全局脚本 → 每 500 ms 触发），它会把变量周期写到 `data/data.json`；页面读不到 REST 时自动用这个文件。

> 这条路只支持「读」，不支持在页面里写值回 PLC。

## 10. 运行选项与部署

设置页 → **运行选项**：

| 选项 | 说明 |
|---|---|
| 自启方式：不启用 | 手动启动 |
| 自启方式：用户登录后启动 | 写入启动文件夹，**不需要管理员**（推荐） |
| 自启方式：开机即启动 | 建计划任务以 SYSTEM 运行，**需要管理员权限**（会生成一个需管理员运行的启用脚本） |
| 启动器 EXE | 生成 `FillViewer.exe`（隐藏黑窗启动器，支持 `-nobrowser`） |
| 启动后自动运行 | 服务就绪后自动用浏览器打开运行画面 |
| 全屏运行 | 浏览器 kiosk 全屏（适合大屏/触摸屏） |
| 默认项目 / 默认模型 | 自动打开哪个项目的哪个模型（留空 = 用项目自己的设置） |

### 10.1 大屏 / 值班室开机即显

推荐组合：`用户登录后启动` + `启动后自动运行` + `全屏运行`，并把浏览器设为开机自启的默认浏览器。这样开机 → 自动全屏显示现场画面，不出现桌面。

### 10.2 局域网其它电脑访问

服务默认**只监听本机**（`127.0.0.1:8099`）。要让车间/大屏机器访问：

1. 编辑 `server.py` 最后几行，把 `host` 由 `"127.0.0.1"` 改成 `"0.0.0.0"`；
2. 在 Windows 防火墙放行 8099（入站规则）；
3. 其它电脑访问 `http://<本机IP>:8099/`。**默认无账号体系，请只在内网使用。**

## 11. 项目、备份与版本历史

### 11.1 一个项目就是一组 JSON

```
projects/<项目id>/
  project.json     项目信息（名称、当前模型文件名）
  bindings.json    绑定    {"items":[…]}
  panels.json      展板    {"items":[…]}
  pipes.json       管线    {"items":[…]}
  panelTpls.json   看板模板
  pipeTpls.json    管线模板
  model/           GLB 模型
  history/         版本历史快照（每次保存自动生成）
```

备份整个项目 = 拷走这个目录。换机器 = 拷过去 + 服务重启后在配置台选中它。

### 11.2 备份与回滚（单文件级）

每次保存，服务端会把上一版另存为 `.bak_<时间戳>`（每类保留 10 份）。设置页「备份与回滚」选类别 → 列出备份 → 一键恢复。

### 11.3 版本历史（整项目级）

每次保存自动给整个项目拍快照（绑定 + 展板 + 管线 + 模板 + 项目信息）。内容没变不会新增。设置页「版本历史」可看到每份快照的时间、来源（手动/保存/恢复前）、包含多少条数据，支持**恢复**与**删除**，保留份数可调（默认 40）。

> 恢复前系统会先给当前状态再存一份，所以回滚本身也可回滚。

## 12. 故障排查

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 打开首页 404 / 打不开 | 服务没起，或端口不是 8099 | 看控制台是否打印 `FillViewer ready`；端口占用时换 `FILLVIEWER_PORT` |
| 画面只有展板，没有模型 | 模型文件没找到 / 项目里模型字段为空 | 配置台设置页确认项目目录与模型文件名；浏览器控制台看 404 的 URL |
| 模型全黑 | 材质金属度=1 且无环境贴图 | 设置页把画质设为「高」（带环境反射），或回 Blender 把 Metallic 调低重导 |
| 设备颜色不跟着变 | 绑定没保存 / 变量没读到 / 变量名写错 | 「全部」页签跑一遍**规则体检**；变量数据页确认真值与时间 |
| 数字一直不变 | 数据源回落到了文件，或变量没在轮询列表 | 看 `/api/live` 的 `src`；设置页把「服务器缓存」设 0 试一次 |
| 电机一直在转但停不下来 | 「启停变量」绑了别的设备或空着 | 绑定页看红字提示，点「改成 <本设备>_YX1」 |
| 旋转越转越快 | 旧版本缺陷 | 升级到最新代码（角度按时间累积，基线只在目标变化时重置） |
| 展板拖不动 | 展板在「跟随对象」模式，或点在卡片文字上 | 勾选「固定位置」再拖；按住卡片空白处拖动 |
| 写入后值又变回去 | PLC 侧在覆盖，或该变量只读 | 变量数据页确认「可写」；查 WinCC 权限与程序逻辑 |
| 改了代码但页面没变 | 浏览器缓存 + 端口上还挂着旧进程 | **Ctrl+F5** 强制刷新；确认旧 Python 进程已退出 |
| 变量读取报 Forbidden | WinCC 未给该变量开 REST 读授权 | 变量属性 → REST API → 勾读权限 |
| 帧率低 / 风扇狂转 | 面数大 + 每帧重绘 | 设置页降低画质；减小模型面数；不要开「强制直读」高频率 |

## 13. 附录

### A. URL 参数（运行画面）

| 参数 | 作用 |
|---|---|
| `?p=<项目id>` | 指定项目 |
| `?m=<模型文件名>` | 覆盖项目里配置的模型 |
| `?poll=<毫秒>` | 轮询间隔（默认 300） |
| `?ttl=<毫秒>` | 服务端缓存时长（默认 200，0 = 每次真读） |
| `?fresh=1` | 强制跳过缓存 |
| `?debug=1` | 右下角显示轮询/耗时/变量数等调试信息 |
| `?fps=<数字>` | 帧率上限（默认 30） |
| `?hq=0` | 关闭高画质（省 GPU） |
| `?vals={"变量":值}` | 用测试值覆盖真实数据（排查用，JSON） |

### B. WinCC REST 速查（本项目用到的部分）

```
读单个   GET  /tagManagement/Value/<变量名>
批量读   POST /tagManagement/Values      body {"variableNames":["A","B"]}
写单个   PUT  /tagManagement/Value/<名>  body {"value":"1"}
批量写   PUT  /tagManagement/Values      body ["1","2"]
```

判据：**看 `errorcode`，不要只看 HTTP 码**（写入失败也常返回 200）。中文变量名在请求体里必须是 UTF-8 原文，不能 `\uXXXX` 转义。变量名里的 `[ ]` 在 URL 中要写成 `%5B%5D`。

### D. 术语

| 词 | 含义 |
|---|---|
| 对象（obj） | 3D 模型里的一个节点，绑定的目标 |
| 绑定（binding） | 对象 + 变量 + 类型 + 参数，描述"数据怎么影响外观" |
| 展板（panel） | 贴在设备旁的实时数据卡片 |
| 管线（pipe） | 若干管道对象组成的一组，做流动/高亮 |
| 变量表（vartable） | 从 WinCC 或 CSV 导入的变量清单（名/注释/可写） |
| 项目（project） | 一个模型 + 一套绑定/展板/管线配置 |
| 数据源（src） | `rest` = 读 WinCC；`file` = 读本地 `data/data.json` |
